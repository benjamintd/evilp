Studying the version-matched HiGHS code is useful because it exposes concrete representations and control paths behind the measured difference. This is a read-only audit of v1.15.1, matching the locked executable's reported version and git hash 04024d7.

The [16-run LP method comparison](../results/lp-method-comparison-v1/REPORT.md)
finds that simplex and interior point both solve the two selected relaxations
quickly. All primals pass original-source checks and all row duals yield valid
lower bounds. These single runs do not rank methods or establish exact
optimality. The original LP profile and this audit inform the next engineering
experiment; they do not open the full benchmark or autoresearch gate.

- **Variable bounds.** `allocateWorkAndBaseArrays()` sizes basic-variable arrays by the number of constraint rows. Column lower and upper bounds go directly into `workLower_` and `workUpper_`; row bounds become bounds on the logical row variables. This keeps bound handling inside simplex's variable state. Inference for MILP Lab: bounded-variable simplex could reduce the enlarged basis dimensions observed in our profile, but that is a larger redesign than changing update storage. [HEkk.cpp, bound initialization](https://github.com/ERGO-Code/HiGHS/blob/v1.15.1/highs/simplex/HEkk.cpp#L2299).

- **Sparse solves and updates.** `HVectorBase` combines a full value array with nonzero indices/counts and optional packed indices/values. `HFactor` selects solve paths using current and expected density, supports multiple update schemes, and defaults to the Forrest–Tomlin update in its ordinary setup. Its upper solve applies updates before the regular triangular solve. These are concrete places to study sparse traversal, dense fallback and refactor decisions. Some kernels also use small-value thresholds; their arithmetic is not a specification for preserving our existing compensated arithmetic or rejection rules. [HVectorBase.h](https://github.com/ERGO-Code/HiGHS/blob/v1.15.1/highs/util/HVectorBase.h), [HFactor.cpp](https://github.com/ERGO-Code/HiGHS/blob/v1.15.1/highs/util/HFactor.cpp#L431).

- **Reoptimization.** Bound changes update nonbasic bound/movement status, invalidate stale solution information and mark simplex data for refresh. `kNewBounds` does not invalidate the basis matrix in the same way as a matrix change. The dual solver explicitly expects an ordinary MIP node basis to start dual feasible. Inference: retaining useful basis/factor state across bound changes is an architectural advantage to measure separately from cold root solves. [HighsInterface.cpp](https://github.com/ERGO-Code/HiGHS/blob/v1.15.1/highs/lp_data/HighsInterface.cpp#L950), [HEkk.cpp](https://github.com/ERGO-Code/HiGHS/blob/v1.15.1/highs/simplex/HEkk.cpp#L293), [HEkkDual.cpp](https://github.com/ERGO-Code/HiGHS/blob/v1.15.1/highs/simplex/HEkkDual.cpp#L53).

- **Degeneracy and numerical recovery.** The inspected dual path chooses cost perturbation according to whether the starting solution is near optimal, maintains steepest-edge or Devex weights, and later removes perturbations during cleanup. Repeated-basis detection records cycling-related bad basis changes and makes selected changes taboo. This is a collection of guarded mechanisms, rather than evidence that one pivot rule explains the entire speed difference. [HEkkDual.cpp](https://github.com/ERGO-Code/HiGHS/blob/v1.15.1/highs/simplex/HEkkDual.cpp#L89), [HEkk.cpp, cycling detection](https://github.com/ERGO-Code/HiGHS/blob/v1.15.1/highs/simplex/HEkk.cpp#L3028).

The code study and the method diagnostic point toward a narrow next engineering question: how much time can our measured sparse update patterns save while preserving the existing numerical contract? They do not establish the answer, justify implementing an interior-point method now, or provide a paper-driven autoresearch result. No production source was changed by this audit.
